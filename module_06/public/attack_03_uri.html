Attack 03 — URI Scheme Injection

Exploiting attributes that accept URLs: href, src, action, formaction, data, xlink:href. The javascript: scheme turns any clickable element into a script executor. The data: scheme creates an inline document the browser trusts.

1
The Open Redirect — Server Trusts Any URL
Reflected — requires click

The /redirect endpoint accepts a url= parameter and calls redirect(url) with no validation. The Location header is set to whatever the attacker supplies. When the scheme is javascript:, the browser executes the expression in the origin of the redirecting page.

/redirect?url=javascript:alert(document.origin)
Fire (new tab)
Click "Analyze" and open DevTools → Network to see the 302 Location header with javascript: value.
2
href Injection — The Direct Vector
Executes on click

When user-supplied data is interpolated into an href attribute without scheme validation, any link on the page can become a JavaScript executor. The payload below injects into the /link-preview endpoint which places it directly in <a href="...">.

/link-preview?url=javascript:alert(document.cookie)
Open Link Preview

On the destination page, click the rendered yellow link. The javascript: URI fires in the origin of localhost:5000.

3
data: URI in an iframe — Framed Document Attack
Zero interaction — auto-executes

A data:text/html, URI creates a full HTML document inline. When injected into an <iframe src=> or loaded via location=, the browser renders it as a real document. Scripts inside it execute in a null origin — but the iframe can reach the parent's DOM if they share the same origin, and can perform phishing-quality overlays regardless of origin.

data:text/html,<script>alert('data URI iframe — origin: '+document.domain)</script>
4
Profile Page — Three Injection Points
Combined M05 + M06 vectors

The /profile page accepts three URL-like parameters. Each maps to a different injection context demonstrating how a single page surface can expose multiple URI injection points simultaneously.

/profile?username=eve&bio=<img src=x onerror=alert(1)>&site=javascript:alert(document.cookie)
Fire Profile Combo

bio= triggers onerror immediately (zero interaction). Then click the "Website" link to fire the javascript: href.

Filter bypass — executes on click

7
DOM Sink: location = "javascript:..."
DOM-based — zero server interaction

When JavaScript reads a URL from the DOM or a query string and assigns it to location, location.href, or location.replace(), the javascript: scheme executes immediately with zero server involvement. This is one of the most common DOM XSS patterns in the wild.

// Vulnerable pattern: const url = new URLSearchParams(location.search).get("next"); location.href = url; // if url = "javascript:alert(1)" → executes
Click to simulate: location.href = "javascript:alert(document.origin)"
