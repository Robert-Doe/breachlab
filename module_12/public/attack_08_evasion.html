01 Keyword blocklist evasion — the incomplete list problem BLOCKLIST
The blocklist trap: a developer blocks script, alert, onerror, onload, javascript. This sounds comprehensive. HTML has 170+ event handlers. The blocklist can never be complete.

Defender lesson: blocklists are the wrong model. An allowlist of safe HTML elements and attributes (via a sanitiser library) is the only viable approach.
02 Script tag stripping — nested tag bypass STRIPPING
The stripping trap: re.sub(r'<script.*?>.*?</script>', '', input) strips script tags. One pass. This is recoverable by the attacker because the regex is applied once to the input — the attacker's payload is reconstructed after stripping.
The nested tag bypass — payload reconstructed after stripping

03 Case variation & character splitting CASE EVASION
Even case-insensitive filters block specific keyword strings. The attacker bypasses by:
  • Using a different function: confirm(1), prompt(1), console.log(1)
  • Using event handlers that don't contain blocked keywords
  • Encoding the payload so the filter sees encoded text but the browser decodes and executes
Bypasses for /filter/case (blocks 'script' and 'alert' case-insensitively)
PayloadBypass technique

04 Encoding bypass — HTML entities & character references ENCODING
The encoding bypass: a filter that blocks raw < and > does not block their HTML entity equivalents: &lt; and &gt;. The browser's HTML parser decodes entities after the filter runs. So the filter sees clean text; the browser sees markup.
Entity forms that bypass raw angle-bracket filters
Entity / encodingDecoded valueContext where it works
&lt; / &gt;< / >HTML entity — decoded in HTML context
&#60; / &#62;< / >Decimal character reference
&#x3C; / &#x3E;< / >Hex character reference
%3C / %3E< / >URL encoding — decoded by server before filter if filter runs on decoded input
The /filter/encoding endpoint blocks literal < and > but renders the output as HTML — so &lt;img src=x onerror=alert(1)&gt; passes the filter and fires in the browser.
Test encoding bypass
Note: This specific bypass only works when the filter inspects the raw input string but renders the output as HTML without re-encoding. If the filter HTML-encodes its output, the entity is double-encoded and renders as text, not markup.

06 WAF bypass — rule ordering and interaction WAF SIM
WAFs apply rules in sequence. Each rule operates on the output of the previous rule. This creates opportunities: a payload that is harmless after rule N-1 can be reconstructed by rule N's transformations.
WAF rule order: strip <script> → block 'alert' → block 'javascript:'
The WAF sim's weakness: Rule 2 blocks 'alert' but only as a plain string replacement. It runs after Rule 1 has already stripped <script> tags. So an img onerror payload carrying confirm() instead of alert() bypasses all three rules.
