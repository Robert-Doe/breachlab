01 OOB receiver — what is an out-of-band callback? CONCEPT
Blind XSS fires in a context the attacker never sees directly — an admin panel, a log dashboard, a PDF generator, an email renderer. The payload executes when a victim (usually a privileged user) views the stored content.

The attacker injects a payload whose only job is to phone home: make an HTTP request to an attacker-controlled server with evidence of execution. This is called an out-of-band (OOB) callback. In production, tools like XSS Hunter and Burp Collaborator provide that callback server. Here, /oob plays that role.

03 PDF generator as a blind XSS surface SERVER-SIDE RENDER
Headless browser–based PDF generators (wkhtmltopdf, Puppeteer/headless Chrome, Prince XML) render HTML before converting to PDF. If user-supplied content is injected into the HTML template without sanitisation, the rendering engine executes the XSS payload — in a server-side, headless context.

Risk: blind XSS in a headless context can read the server's local files via file:/// (wkhtmltopdf SSRF), access internal APIs, or exfiltrate the generated PDF's content.

04 Email template renderer as a blind XSS surface EMAIL RENDERER
Applications that render HTML email previews in a browser — enterprise webmail, email marketing dashboards, notification preview panels — are blind XSS surfaces if the email body isn't sanitised.

The attacker sets their "display name" or a field that ends up in an email subject or body. When the admin previews the email template, the payload fires in the admin's browser.

06 Dwell time & persistence — the blind XSS advantage THEORY
Blind XSS payloads often persist in storage for extended periods. Unlike reflected XSS (which requires the victim to click a link), a stored blind payload fires every time any privileged user views the surface — potentially days, weeks, or months after initial injection.
CharacteristicReflected XSSBlind Stored XSS
Victim must click a linkYesNo — admin navigates normally
Attacker sees responseYes (same session)No — out-of-band only
PersistenceNone (single use)Persists until record deleted
TargetsAnyone with the linkAdmins / privileged viewers
DetectionEasier (URL-based)Harder (no URL evidence)
Privilege escalationRareCommon (admin cookie / token)
Common real-world blind XSS surfaces:
  • Customer support ticket systems (Zendesk, internal helpdesk)
  • Application log dashboards (Kibana, Splunk, Grafana annotations)
  • PDF/report generators (wkhtmltopdf, Puppeteer pipelines)
  • Transactional email preview panels
  • Admin user management interfaces (username/bio fields)
  • Error reporting dashboards (Sentry, custom error logs)
  • Contact/feedback forms rendered in admin CRM
