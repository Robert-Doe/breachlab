A. Basic <script> Variants
TAG PARSING BASELINE
01
<script>alert(document.domain)</script>
ContextHTML body — directly injected between tags Mechanism1 — Tag parsing: browser sees <script> as a new script block BypassesNothing — the absolute baseline. No filter evasion. Stopped byOutput encoding (< → &lt;); CSP without unsafe-inline; any HTML sanitizer OriginThe first XSS payload every developer tests. Establishes whether the sink is injectable at all.

ContextHTML body Mechanism1 — Tag parsing (HTML is case-insensitive) BypassesFilters that match only lowercase script Stopped byCase-insensitive string matching; output encoding; CSP OriginClassic WAF evasion. HTML spec requires case-insensitive tag name matching.
TAG PARSINGFILTER BYPASS
03
<script/>alert(1)</script>
ContextHTML body Mechanism1 — Tag parsing: slash after tag name is ignored by tolerant parsers BypassesFilters requiring <script> exactly (with closing > but no slash) Stopped byOutput encoding; CSP; proper HTML sanitizer OriginHTML5 error recovery: self-closing slash on non-void elements is ignored. Parser still opens a script block.
TAG PARSINGFILTER BYPASS
04

Used to bypass paren-blocking WAFs.
B. Encoding & Splitting Tricks
TAG PARSINGENCODING
05
<script>eval(atob('YWxlcnQoZG9jdW1lbnQuZG9tYWluKQ=='))</script>
ContextHTML body — payload JS is base64-encoded Mechanism1 — Tag parsing; inner payload is obfuscated with base64 BypassesKeyword filters blocking alert, document, cookie in the string itself Stopped byCSP (blocks eval by default); output encoding on the outer tag; sandbox environments that disable eval OriginStandard obfuscation layer. The base64 string decodes to alert(document.domain). Replace the encoded string for any payload.

ContextURL parameter that is URL-decoded before being reflected into HTML Mechanism1 — Tag parsing after server URL-decodes the parameter BypassesFilters that check the raw URL string before decoding Stopped byChecking the decoded value; output encoding on the decoded value before HTML insertion OriginStandard URL encoding. %3C=<, %3E=>, %2F=/. Server decodes → injects raw tag.
TAG PARSINGFILTER BYPASS
08
<script>//<![CDATA[ alert(1) //]]></script>
ContextXHTML or XML page where CDATA sections are valid Mechanism1 — Tag parsing in XML mode; CDATA allows literal < and > inside BypassesSome XML-aware sanitizers that treat CDATA as non-executable Stopped byServing as text/html not application/xhtml+xml; CSP; output encoding OriginXHTML-specific. In XHTML, script content is CDATA so < and > are literal. Has appeared in SVG-embedded pages.
C. Exotic Script Tag Forms
TAG PARSINGFILTER BYPASS

ContextHTML inside existing <script> block where attacker data is embedded in a comment Mechanism1 — Escaping from a JS comment via </script> which closes the current script block BypassesTemplates that put user data inside JS comments thinking it's safe Stopped byJSON-encoding user data inside script blocks; never embedding raw user data in JS OriginThe </script> sequence inside a script block closes it at the HTML level, even mid-comment. The engine resolves them before execution. The string "alert" never appears in the payload.
