A. SVG — Inline Script Execution
TAG PARSINGSVG
01
<svg><script>alert(1)</script></svg>
ContextHTML body — SVG namespace includes its own <script> element Mechanism1 — Tag parsing: SVG <script> executes JavaScript same as HTML <script> BypassesSanitizers that check for script tags only in the HTML namespace Stopped byCSP; sanitizers that check all namespaces; blocking SVG entirely OriginSVG is a full XML namespace with its own script element. When embedded inline in HTML5, it runs in the same origin. "Just an image" is a dangerous mental model.
EVENT ATTRSVG
02
<svg><animate onbegin=alert(1) attributeName=x></animate></svg>
ContextHTML body — SVG animate element has onbegin event that fires when animation starts Mechanism2 — Event attribute in SVG namespace; fires automatically on parse BypassesFilters blocking HTML event handlers but not SVG animation event handlers Stopped byCSP; SVG-aware sanitizers stripping onbegin; blocking animate element OriginSVG SMIL animation elements (animate, set, animateTransform) have their own event model including onbegin, onend, onrepeat. These are distinct from HTML event attributes but equally powerful.
TAG PARSINGSVGFILE UPLOAD
03
<?xml version="1.0" encoding="UTF-8"?> <svg xmlns="http://www.w3.org/2000/svg" onload="alert(document.domain)"> <circle cx="50" cy="50" r="40" fill="red"/> </svg>
ContextSVG file served as image/svg+xml — or embedded inline after upload Mechanism2 — Event attribute: onload on SVG root fires when document loads BypassesUpload filters that check file extension/MIME but serve the file same-origin; image-only file checks Stopped byServing SVG from a separate domain; X-Content-Type-Options: nosniff; CSP on the serving domain OriginWhen an SVG is served same-origin as image/svg+xml and loaded in a <img> tag, the script doesn't run. But when it's served as a file download link or directly navigated to, it executes. The classic SVG upload XSS.
SVGFILTER BYPASS
04
<svg><desc></desc><set attributeName=onmouseover to=alert(1)></set></svg>
ContextHTML body — SVG set element changes attributeName from nothing to an event handler Mechanism2 — SVG SMIL animation sets an event attribute on the parent element BypassesSanitizers that check static attributes at parse time but don't account for SMIL-based dynamic attribute setting Stopped byBlocking SVG animation elements (set, animate, animateTransform); CSP OriginSMIL <set> changes an attribute value dynamically. Setting attributeName=onmouseover and to=alert(1) writes an event handler onto the element after parse — bypassing static attribute checks.
B. MathML Namespace Escapes
MATHMLNAMESPACE ESCAPE
05
<math><mtext></mtext></math><img src=x onerror=alert(1)>
ContextHTML body — closing MathML correctly allows HTML to follow Mechanism2 + namespace: escape from MathML context back to HTML, then event handler fires BypassesSanitizers that see the MathML block as a safe contained namespace and don't parse what follows Stopped byDOM-based sanitizers that parse the full document; output encoding; CSP OriginMathML is an HTML5 namespace like SVG. Once properly closed, the parser returns to HTML context. The img tag that follows is valid HTML. Used in mXSS research to demonstrate namespace boundary issues.
MATHMLNAMESPACE ESCAPE
06
<math><mtext><table><mglyph><style></style></mglyph><img src onerror=alert(1)></table></mtext></math>
ContextHTML body — complex MathML/HTML namespace interplay; a mXSS vector Mechanism5 — Context escape + reparse: mglyph inside mtext creates an annotation-xml integration point; table inside creates further parsing complexity; the result after innerHTML round-trip differs from original BypassesString-based sanitizers; sanitizers that parse once but don't account for mXSS Stopped byDOMPurify (blocks this class); CSP; blocking MathML OriginMutation XSS vector discovered in 2019. The combination of MathML annotation-xml integration points, foster parenting from table, and style element raw-text mode creates a parser state machine that produces different output on re-parse.
C. iframe srcdoc — Entity Decoding Layer
URI SCHEMESRCDOC
07
<iframe srcdoc="&lt;script&gt;alert(parent.document.domain)&lt;/script&gt;"></iframe>
ContextHTML body — srcdoc content is HTML-entity encoded, decoded by browser before parsing Mechanism1 — Tag parsing in sub-document; srcdoc decodes entities → produces <script> tag BypassesSanitizers that see &lt;script&gt; as safe text content; filters checking for literal <script> Stopped bySanitizers treating srcdoc as HTML (decoding entities before checking); CSP; blocking iframe srcdoc Originsrcdoc attribute content is parsed as HTML after entity decoding. A sanitizer that checks the attribute value sees &lt;script&gt; (looks like escaped text). The browser decodes and sees an actual script tag.
SVGFILTER BYPASS
08
<svg><style></style><img src=x onerror=alert(1)></svg>
ContextHTML body — style element inside SVG is raw text (CDATA) context; img that follows may be parsed as HTML depending on parser state Mechanism5 — Context escape: in SVG context, style is raw text; after serialization and re-parse in HTML context, style content ends at </style> and img is free HTML BypassesSanitizers that model SVG/style context incorrectly in mXSS scenarios Stopped byDOMPurify; CSP; avoiding innerHTML round-trips OriginClassic mXSS vector (M13). In SVG context, <style> is raw text — so <img…> inside it is just text. Serialized: <svg><style></style><img…></svg>. Re-parsed in HTML: style ends at </style>, img becomes HTML.
D. Namespace Switching in Attribute Contexts
SVGEVENT ATTR
09
<svg><a xlink:href="javascript:alert(1)"><text y=20>click</text></a></svg>
ContextSVG namespace — xlink:href allows javascript: URI on SVG anchor elements Mechanism3 — URI scheme via SVG xlink:href attribute BypassesSanitizers checking HTML href but not SVG xlink:href for javascript: Stopped bySanitizers that normalise xlink:href to href and apply same checks; CSP Originxlink:href is the SVG/XML linking attribute. It accepts javascript: just like HTML href. Many sanitizers check href but miss xlink:href because it's a different attribute name with a namespace prefix.
SVGFILTER BYPASS
10
<svg><foreignObject width="100%" height="100%"> <div xmlns="http://www.w3.org/1999/xhtml"> <img src=x onerror=alert(1)> </div> </foreignObject></svg>
ContextHTML body — SVG foreignObject embeds HTML namespace inside SVG Mechanism2 — Event attribute in HTML namespace embedded inside SVG foreignObject BypassesSVG-specific sanitizers that don't parse foreignObject content as HTML Stopped byBlocking foreignObject in SVG sanitization rules; CSP; DOMPurify OriginforeignObject is explicitly designed to embed HTML inside SVG. The xmlns declaration switches the parser back to HTML namespace. The img tag inside is full HTML with event handlers. This is why SVG file upload filters must check foreignObject.
MATHMLANNOTATION
11
<math><annotation-xml encoding="text/html"><img src=x onerror=alert(1)></annotation-xml></math>
ContextHTML body — MathML annotation-xml with HTML encoding creates an HTML integration point Mechanism2 + namespace: annotation-xml with encoding="text/html" is an HTML integration point — content is parsed as HTML BypassesSanitizers that treat annotation-xml as XML text content; filters missing the HTML integration point semantics Stopped byDOMPurify; blocking annotation-xml; CSP OriginThe HTML5 spec defines annotation-xml with encoding="text/html" (or "application/xhtml+xml") as an "HTML integration point" — content switches to HTML parsing mode. The img tag inside is parsed as HTML with full event model.
