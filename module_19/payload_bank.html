How to read each payload entry: Every payload in the sub-pages follows this structure: Payload (copy-paste ready) → Context (where in HTML it lands) → Mechanism (which of the 5 from M03) → Bypasses (what filter/defense it defeats) → Stopped by (what would prevent it) → Origin (CVE, bug bounty, worm, research).

How to use the Payload Bank

  1. Open a category page below
  2. Read the annotation before testing — understand why before you try
  3. Start the lab server from any previous module (make py)
  4. Test the payload against the appropriate endpoint (noted per payload)
  5. Observe: does the alert fire? Check browser DevTools if not — the error tells you which defense blocked it
  6. Try the "what stops it" defense — confirm the payload is blocked

Quick-Reference: The 5 Mechanisms

Every payload in this bank reduces to one of these five execution mechanisms (from Module 03). Knowing which mechanism a payload uses tells you immediately which defense stops it.

#MechanismExample triggerPrimary defense
1Tag parsing <script>…</script> Output encoding, CSP script-src
2Event attributes <img onerror=…> Output encoding, CSP unsafe-inline off
3URI schemes <a href="javascript:…"> URL allowlist, CSP script-src
4DOM sinks el.innerHTML = location.hash Trusted Types, safe DOM API (textContent)
5Context-escape + reparse " onmouseover=" breaking out of attribute Output encoding in correct context
