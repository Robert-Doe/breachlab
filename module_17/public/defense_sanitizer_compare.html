Why string sanitizers fail

Regex/string-replace sanitizers fail because HTML is not a regular language. The browser's HTML parser handles malformed markup, namespace switching (SVG/MathML), and legacy quirks in ways that cannot be fully captured by a regular expression.

The mXSS preset above demonstrates this: the MathML foster parenting sequence creates a context where <style> is raw text in the sanitizer's parser but active HTML in the browser's re-parse. A regex sanitizer sees no script tags and no event handlers — but the browser executes the payload.

Correct approach: Parse the HTML using a real HTML parser, walk the AST and remove dangerous nodes, then serialize. This is what DOMPurify does — it uses the browser's own parser as the parsing engine, then inspects and strips the resulting DOM.
