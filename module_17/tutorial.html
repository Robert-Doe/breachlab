1. Defense Layer Model

No single defense stops all XSS. The industry approach is defense-in-depth: multiple layers that each stop a different class of attack, so an attacker who defeats one layer still hits the next.

LayerDefenseStopsDoesn't stop
1Output encodingReflected + stored XSS in HTML contextDOM-based XSS, template injection
2Parameterized templatesServer-side template injection → XSSClient-side DOM sinks
3HTML sanitizationRich-text/HTML input in display contextsmXSS, parser divergence, context mistakes
4Content Security PolicyInline script execution, external script loadsDOM sinks fed by allowed scripts; data: / blob: misconfig

6HttpOnly cookiesCookie theft via document.cookieForged requests using cookie (cookie still sent by browser)

2. Output Encoding — The Foundation

Output encoding converts characters that have meaning in the target context into their harmless escaped equivalents. The key word is context — the encoding rules differ by where the data lands.

ContextDangerous charsCorrect encodingFunction (Python / JS)
HTML body< > & " '&lt; &gt; &amp; &quot; &#39;html.escape() / textContent
HTML attribute< > & " 'Same + must be in quoted attributehtml.escape()
JavaScript string\ ' " </script> \nJSON-encode or \x / \u escapejson.dumps()
CSS value; { } expression(CSS-encode or whitelist valuesWhitelist only
URL parameterEverything except unreserved charsPercent-encodeurllib.parse.quote() / encodeURIComponent()

The Context Mistake

# WRONG — HTML encoding applied in JS context
<script>
  var name = "{{ html_escape(user_name) }}";
//              ^ &lt; becomes &lt; in the string — wrong encoding
</script>

# CORRECT — JSON encode for JS string context
<script>
  var name = {{ json.dumps(user_name) }};
//              ^ produces "Alice
