DOM XSS Lab

Each card below contains intentionally vulnerable JavaScript. The vulnerability lives entirely in the browser — no server involvement needed.

SOURCE → processing / assignment → SINK (executes) — DOM XSS: attacker controls data flowing from a source to a sink
Sinks — innerHTML family
innerHTML
SINK source: location.hash
Reads location.hash (the fragment after # — never sent to server) and assigns it to innerHTML. Hash-based DOM XSS is undetectable in server logs.
// Vulnerable code: const term = location.hash.slice(1); // source document.getElementById('s1-out').innerHTML = term; // sink
Output here
insertAdjacentHTML
SINK source: URLSearchParams
insertAdjacentHTML is functionally identical to innerHTML in terms of script execution rules — it parses and renders HTML including event handlers. Developers sometimes believe it is "safer" than innerHTML. It is not.
const q = new URLSearchParams(location.search).get('q'); // source document.getElementById('s2-out').insertAdjacentHTML('beforeend', q); // sink
Output here
document.write
SINK source: document.referrer
document.write is a legacy DOM API that writes directly into the document stream. It parses its argument as HTML in the current document context. Script tags written via document.write do execute — unlike the innerHTML restriction. Source is document.referrer, which can be controlled by hosting a page that links to this one.
// Simulating: const src = document.referrer; // In this demo the source is the input field. document.write('<div>Came from: ' + userInput + '</div>'); // sink

After firing, the entire page is replaced by document.write output — use browser Back to return.

Sinks — JavaScript execution
eval()
SINK source: location.search
eval() executes its string argument as JavaScript directly. The payload does not need to be HTML — it is raw JavaScript. This makes eval-based DOM XSS simpler: no HTML tags, no event handlers, just alert(1) directly.
const expr = new URLSearchParams(location.search).get('expr'); eval(expr); // executes attacker JS directly — no HTML parsing needed
setTimeout(string)
SINK source: location.hash
setTimeout and setInterval accept either a function or a string. When passed a string, they behave like eval() — the string is executed as JavaScript after the delay. Developers often use the string form for simplicity and don't recognise it as a sink.
const code = location.hash.slice(1); setTimeout(code, 100); // string form — equivalent to eval()
location / location.href
SINK source: URLSearchParams
When a URL value from a source reaches a location assignment, javascript: scheme executes. This is the most common DOM XSS pattern in single-page applications that implement their own routing using ?next= or #return= parameters.
const next = new URLSearchParams(location.search).get('next'); location.href = next; // if next = "javascript:..." → executes

After firing, use browser Back to return.

JSON API → innerHTML
SINK source: fetch /api/search DOM XSS via AJAX
Fetches /api/search?q= and renders response.query via innerHTML. The server returns the query safely in JSON — the vulnerability is in the client-side rendering.
fetch('/api/search?q=' + userQuery) .then(r => r.json()) .then(data => { el.innerHTML = 'Results for: ' + data.query; // sink });
