Samy Worm — MySpace, October 2005

SELF-PROPAGATING FILTER BYPASS Author: Samy Kamkar  |  Impact: ~1,000,000 profiles in 20 hours  |  Module: M16

Background

In October 2005, Samy Kamkar injected a self-replicating XSS payload into his MySpace profile. MySpace allowed customisation of profile pages via HTML, but applied a filter to block JavaScript. Samy bypassed this filter and created the first large-scale XSS worm. Every user who visited his profile had their own profile infected with the same payload — which also added Samy as a friend and posted "but most of all, samy is my hero."

Within 20 hours, approximately 1,000,000 MySpace accounts were infected. MySpace took the site offline to remove infected profiles. Samy pled guilty to a felony under the California Computer Crime Law and was sentenced to community service, probation, and banned from using computers for three years.

The Filter and How It Was Bypassed

MySpace's filter blocked obvious JavaScript patterns: the word "javascript", <script> tags, onclick, and other event handlers. It also blocked CSS expression() — but imperfectly.

Samy discovered that Internet Explorer supported CSS expressions (background: url('javascript:...')) and that MySpace's filter checked for the exact string "javascript" — which could be split across a line boundary:

/* The key bypass — newline inside the keyword */
background: url('java
script:...')

/* IE joined the split string and evaluated it */
/* MySpace's filter saw "java" and "script" separately — no match */

The actual payload was injected via a CSS style attribute on a <div> inside the profile. The filter allowed style= attributes but didn't correctly handle the line-break bypass.

Filter bypass lesson: Blocklist filters on string patterns are fundamentally fragile. Any filter that checks for "javascript" as a literal string can be bypassed by inserting whitespace, line breaks, null bytes, or encoding variants. The correct defense is an allowlist (permit only known-safe HTML elements and attributes), not a blocklist.

Worm Propagation Logic (Reconstructed)

The payload performed three actions on every victim's browser:

/* Step 1: Add Samy as a friend */
/* XHR to /addFriend?id=11851658 */

/* Step 2: Post "but most of all, samy is my hero" to the victim's hero section */
/* XHR to /updateProfile with the text */

/* Step 3: REPLICATE — copy the worm payload into the victim's own profile */
/* XHR GET to /viewProfile to read CSRF token */
/* XHR POST to /updateProfile with full worm payload */

/* Every visitor → infected profile → infects next layer of visitors */

The CSRF bypass was possible because MySpace's AJAX calls included the CSRF token in the HTML — and the same-origin XHR could read it. MySpace did not have SameSite cookies or per-request nonces at the time.

Three Conditions for a Worm

The Samy worm illustrates that XSS worms require three specific conditions. Breaking any one of them stops propagation:

  1. Stored XSS sink — a field that stores user input and renders it to other users without encoding.
  2. Write-back capability — the payload can update the current user's profile/post (requires either no CSRF protection or CSRF token harvesting).
  3. Social visibility — the infected field is displayed to other users (profile visitors, followers, friends).

Missing Defenses

Missing

Output encoding on profile display — bio/hero fields inserted directly into HTML

Fix

html.escape(bio) before inserting into template — converts < to &lt;

Missing

Allowlist HTML filter — blocklist on "javascript" string bypassed by line break

Fix

Allowlist sanitizer (DOMPurify) — permit only known-safe tags, block all others by default

Missing

Rate limiting on profile updates — worm posted unlimited updates

Fix

Rate limit profile-update API per user per minute; CAPTCHA for high-frequency updates

Missing

CSP — no policy to block inline script or restrict XHR targets

Fix

Content-Security-Policy: script-src 'nonce-…'; connect-src 'self'

PhD-Level Observations

The Samy worm is the first empirical demonstration of XSS worm propagation at scale. Several observations remain relevant to research:

  1. Exponential spread rate (each profile infects all its visitors) matches SIR epidemic models. The R₀ of the Samy worm was approximately (average friend count of an infected user) — estimated at 10–50 for MySpace circa 2005.
  2. The worm bypassed CSRF protection via same-origin XHR — confirming that CSRF tokens provide no protection against XSS-driven requests.
  3. Detection was by volume anomaly (unusual profile update rate), not by content inspection. This suggests monitoring API call rates per user as a detection layer complementary to input validation.
  4. The patch required both encoding fix AND profile cleanup — the encoding fix alone would not remove already-infected content.
