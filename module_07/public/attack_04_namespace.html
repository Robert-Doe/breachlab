Attack 04 — Tag & Namespace Confusion

The HTML5 parser runs in three namespaces: HTML, SVG, and MathML. Switching between them changes parsing rules in ways that sanitisers frequently miss.

1
SVG: script tag executes (unlike innerHTML)
SVG namespace

In Module 05 we saw that <script> tags injected via innerHTML do not execute. This restriction applies only to HTML namespace parsing. When a <script> tag appears inside an <svg> element in server-rendered HTML, the HTML5 parser treats it as a foreign-content script and it does execute.

/svg-inject?q=<script>alert('SVG script — executed in ' + document.domain)</script>
Fire on server
Click Demo in DOM
Click "Fire on server" → script runs
2
SVG onload — zero interaction
ZERO INTERACTION

<svg onload=...> fires the moment the SVG element is parsed. This is the single most portable zero-interaction vector: it works in server-rendered HTML, in innerHTML injection (via onload on the svg tag), and in stored XSS contexts.

/svg-inject?q=</svg><svg onload=alert(document.domain)>
Fire

The </svg> prefix closes the existing SVG tag, placing the new <svg onload=...> in HTML context where onload fires normally.

3
SVG animate/set — scriptless execution
SVG namespace ZERO INTERACTION

SVG has its own animation elements: <animate>, <set>, and <animateTransform>. These can target attributes on other elements — including event handler attributes. Setting an attribute like onmouseover via animation bypasses sanitisers that check attribute values at parse time but do not account for post-parse mutations.

<svg><a><animate attributeName=href values=javascript:alert(1) /><text y=20>click</text></a></svg>
Inject, then click the "click" text that appears.
4
SVG foreignObject — HTML island inside SVG
SVG → HTML namespace switch

<foreignObject> is an SVG element that embeds an HTML (or other namespace) document inside SVG. The embedded content is parsed in HTML namespace — all HTML XSS vectors apply. A sanitiser operating on SVG elements that does not recurse into foreignObject misses the embedded HTML entirely.

<svg><foreignObject width=100% height=100%><body xmlns="http://www.w3.org/1999/xhtml"><img src=x onerror=alert('foreignObject — HTML inside SVG')></body></foreignObject></svg>
The onerror fires in HTML context embedded inside SVG.
5
MathML — event handler on mtext
MathML namespace

MathML elements support event handler attributes. <mtext> is a common injection target — it accepts HTML content as children, creating a namespace boundary that some sanitisers fail to traverse correctly.

/math-inject?q=<mtext><img src=x onerror=alert('MathML injection')></mtext>
Fire on server
6
iframe srcdoc — same-origin script execution
SAME-ORIGIN ACCESS

An iframe with srcdoc and no sandbox attribute (or with sandbox="allow-scripts allow-same-origin") runs in the same origin as the parent. Any script executing inside it has full access to parent.document, parent.localStorage, and parent.document.cookie. This is more dangerous than a data: iframe (which runs in null origin).

/iframe-inject?q=<script>parent.document.title='HIJACKED by srcdoc script';</script>
Fire on server

After firing, check the browser tab title — the iframe script modified the parent's document.title via parent.document.
